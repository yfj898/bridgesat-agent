# Task 2 Collision Classification and Rollback Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make RLS-hidden cross-tenant global-ID collisions deterministic non-retryable sync rejections and ensure rollback cleanup never replaces a primary exception.

**Architecture:** Keep global identifiers globally unique and classify database conflicts at the existing per-event savepoint boundary. Visible same-tenant ownership probes continue to decide duplicate versus foreign-student behavior; only an allowlisted PostgreSQL identity constraint with no visible owner becomes `INVALID_SCHEMA`. Replace redundant explicit rollback calls with quiet cleanup while retaining transaction boundaries and lock release behavior.

**Tech Stack:** Python 3.11+, FastAPI domain services, psycopg 3, PostgreSQL RLS, pytest.

- [x] **Step 3: Extend `_global_id_collision` without changing visible-owner semantics**

Keep the existing learning-event and answer-attempt owner probes first. If either probe finds a different visible student, return the existing non-retryable `EventValidationError`. If the owner is the current student, return `None` so same-student duplicate behavior remains unchanged.

After those probes, inspect `unique_error.diag.constraint_name`. If it is in `_GLOBAL_ID_CONSTRAINTS` and no visible owner was found, return:

```python

    "Global sync identifier is already owned outside the current tenant",
    code=SyncErrorCode.INVALID_SCHEMA,
    retryable=False,
)
```

For every other constraint name, return `None` so the original database exception remains fatal.

### Task 4: Make rollback cleanup quiet and scoped

**Files:**
- Modify: `app/sync/service.py`
- Modify: `app/memory/deletion.py`

- [x] **Step 1: Remove or quiet redundant SyncService rollbacks**

For `register_device`, `revoke_device`, and the `StudentInactiveError` path in `process_batch`, rely on the surrounding `transaction()` context where it already owns rollback. If an explicit rollback is retained for connection cleanup, wrap it in `try/except BaseException: pass` and re-raise/return the original outcome.

- [x] **Step 2: Quiet manual deletion rollback paths**

Wrap rollback calls in `request_deletion`, `execute_sqlite_deletion`, and `_set_state` with the established pattern:

```python
except BaseException:
    try:
        self.connection.rollback()
    except BaseException:
        pass
    raise
```

Do not alter the already-correct `_finalize_verified` and `complete_index_deletion` behavior beyond avoiding duplicate cleanup.
